Workflow 1 · Problem Sensing (and Response)

Signal Desk

A working problem-sensing and response pipeline: scan recurring AI-tooling complaints, rank them into an opportunity matrix, then draft (never auto-send) outreach to the people describing the pain.

Team · Divya, Noa, Sreya, Harsh Course · AI Tools for Venture Workflows, Session 1
01 · Method

How we picked terms and platforms

We did not start with a venture idea. We let the scan surface one, so the picking process itself needed to be disciplined.

Search lexicon

Broad emotion terms alone returned marketing copy, not complaints. We layered three word classes together.

product names Cursor Claude Code Copilot Operator Comet + symptom words loses context hallucinate repeats itself + venue filter site:reddit.com site:news.ycombinator.com

Platforms scanned

  • Reddit (search index + direct fetch attempts)
  • Hacker News (search index + item pages)
  • GitHub Issues on public agent repos
  • G2 and review aggregators
  • Dev.to and technical Substacks
  • X / Twitter · attempted, no free access (see slide 09)

03 · Chosen opportunity

Context loss in long agentic coding sessions

The people describing this are specific, findable, and already paying for the tools that are frustrating them, which makes them reachable for customer discovery, not just a survey population.

What we actually found

  • anthropics/claude-code #92951, "Agent loses context and makes repeated mistakes during extended sessions"
  • Dev.to: "Why Your Claude Code Sessions Keep Losing Context (And How to Fix It)"
  • Dev.to: "Why Does Claude Code Lose Track Mid-Task?"
  • Substack: a user reverse-engineering why /compact discards useful context

Who is most concentrated here

Developers running multi-day or multi-hundred-tool-call agent sessions on Claude Code, Cursor, Windsurf, and Copilot, most visible in GitHub issue threads on those repos and in r/ClaudeAI and r/cursor.

The tell that this is a real wedge, not just noise: people are already hand-rolling fixes (checkpoint files, manual spec re-statements) instead of waiting for the vendor.

06 · Prompt design

The two prompts doing the real work

Prompt A: cluster and score 
You are a research analyst screening startup problem signal.
For each raw item I give you (from GitHub issues, forums, or reviews):

1. Assign it to a problem cluster. Name the cluster as a specific
   failure in a job-to-be-done, not a vague category.
2. Score FREQUENCY 1-5, how often this same complaint recurs.
3. Score SEVERITY 1-5, how much workflow, financial, or trust
   damage the complaint describes.
4. Note WHERE CONCENTRATED, platform, subreddit, or repo.
5. Flag it if the poster describes a workaround they built
   themselves. That is a stronger signal than the complaint alone.

Return one row per cluster, aggregating duplicates, as a table.

Raw items: [paste scraped items]
Prompt B: draft a reply (astroturf guardrails built in) 
Draft a reply from [founder name], building tooling for [cluster].
Here is the exact complaint and source link: [paste complaint + link]

Rules:
- Under 80 words. Sign with the founder's real name.
- Reference the specific detail they described, not a summary.
- Offer something useful first (a workaround, a direct answer)
  before making any ask.
- If asking for time, frame it as customer discovery, never as a
  pitch or a beta invite.
- Do not claim experience we do not have.
- If the exchange goes past one reply, disclose we are building
  something in this space.
- No marketing language.

08 · The trade-off

Fast and easy versus astroturfing

The same automation that makes outreach cheap for a founder is what makes it read as manufactured if we are not careful. Here is where we drew the line.

01Every reply discloses a real name and, past one exchange, that we are building something in this space. No sock accounts, no "just a fellow user" framing.
02The draft always offers something before it asks for anything, a workaround, a direct answer, a resource, never an ask-first message.
03Automation stops at the draft. A person reads, edits, and approves every message before it posts or sends. Nothing goes out unattended.
04Volume is capped intentionally. A founder who replies to forty threads a day in identical cadence reads as a bot even when a human wrote every word.
05Every sent message is logged, so the team can check for repetition or drift toward generic, scripted-sounding language over time.
09 · What did not work

Real limitations we hit building this

Direct scraping got blocked

Fetching Reddit's own search pages directly was blocked outright. Hacker News item pages rate-limited us on a second request. Confirms the assignment's own tool list: you need F5Bot, Syften, or an official API, not ad hoc fetching.

Broad queries returned marketing, not complaints

"AI agent frustrating" mostly surfaced explainer blogs and thought-leadership about agents. Real complaint density only showed up once we narrowed to a specific product name plus a specific symptom word plus a specific venue like GitHub issues or dev.to.

X was a dead end on the free tier

No free path to X search turned up real posts. The sample tool list treats X API/MCP as a given, but it is a real gap unless someone on the team already has paid access.

Aggregator sites validate a pattern, not a lead

G2 and review-aggregator content confirmed the support-agent cluster is real at category scale, but gave us nothing individually addressable to actually message. Good for sizing a problem, useless for sourcing outreach targets.
